# Feature specs

## 1) Guided onboarding + first-job magic

repo 已经有 `onboard`、`doctor`、`run`、部署模式，甚至有面向代理的引导文本/技能端点，但也有当前的引导/认证验证问题和一个开放的"引导失败"报告。这意味着这不仅仅是打磨；这是产品关键的。（[GitHub][1]）

### Product decision

用"面试优先引导"替换"配置优先引导"。

### What we want

-  upfront 问 3-4 个问题，而不是 20 个设置。
- 自动生成正确路径：本地单人、共享私有或公共云。
- 检测已经存在什么代理/运行时环境。
- 让 Claude/OpenClaw/Codex 帮助完成设置变得正常。
- 以一个真正的第一个任务结束引导，而不是空白仪表板。

### What we do not want

- 在价值之前的提供商术语。
- "去找 API 密钥"作为默认第一条指令。
- 成功的安装仍然让用户不确定下一步该做什么。

### Proposed UX

首次运行时，显示面试：

```ts
type OnboardingProfile = {
  // 工作类型
  workType: 'development' | 'research' | 'automation';
  
  // 团队规模
  teamSize: 'solo' | 'small' | 'large';
  
  // 部署偏好
  deployment: 'local' | 'cloud' | 'hybrid';
  
  // 初始目标
  initialGoal?: string;
}
```

面试之后，生成配置并创建第一个真实任务。

## 2) Skills-first company templates

Paperclip 应该支持技能优先的公司模板。

### What this means

用户选择技能包而不是手动配置。

### Proposed UX

模板市场：

```
Local Dev Starter
├── Skills: paperclip, claude-code
├── Agents: CEO, Engineer
└── Goal: 自动化本地开发

Research Team
├── Skills: paperclip, researcher
├── Agents: CEO, Researcher
└── Goal: 研究和报告
```

## 3) Task-first UX

Paperclip 应该支持任务优先 UX。

### What this means

用户创建任务而不是配置代理。

### Proposed UX

创建任务：

```
Name: Build landing page
Type: development
Agents: Engineer, Designer
Budget: $50
```

Paperclip 自动配置代理并开始工作。

## 4) Budget-first governance

Paperclip 应该支持预算优先治理。

### What this means

用户设置预算而不是手动管理代理。

### Proposed UX

设置公司预算：

```
Monthly Budget: $1000
Alert at: 80%
Hard stop at: 100%
```

Paperclip 自动管理代理成本。

## 5) Progressive complexity

Paperclip 应该支持渐进复杂性。

### What this means

用户从简单开始，然后根据需要添加复杂性。

### Proposed UX

开始：

- 只需任务和目标
- 简单的代理配置
- 基本预算

然后添加：

- 高级代理配置
- 技能管理
- 复杂预算规则
