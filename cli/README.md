## 什么是 Paperclip？

# 零人类公司的开源编排系统

**如果 OpenClaw 是一名 _员工_，那么 Paperclip 就是一家 _公司_**

Paperclip 是一个 Node.js 服务器和 React UI，用于编排一支 AI 智能体团队来运营业务。带上你自己的智能体，分配目标，从一个仪表板跟踪智能体的工作和成本。

它看起来像一个任务管理器——但内部实际上包含组织结构图、预算、治理、目标对齐和智能体协调。

**管理业务目标，而不是管理拉取请求。**

|        | 步骤            | 示例                                                            |
| ------ | --------------- | ------------------------------------------------------------------ |
| **01** | 定义目标 | _"打造排名第一的 AI 笔记应用，达到 100 万美元月收入。"_                    |
| **02** | 组建团队   | CEO、CTO、工程师、设计师、营销人员——任何机器人，任何提供商。 |
| **03** | 审批并运行 | 审查策略。设定预算。启动。从仪表板监控。  |

<br/>

> **即将推出：Clipmart** — 一键下载并运行整个公司。浏览预构建的公司模板——完整的组织结构、智能体配置和技能——并在几秒内将它们导入到你的 Paperclip 实例中。

## 如果你有以下需求，Paperclip 适合你

- ✅ 你想建立 **自主 AI 公司**
- ✅ 你需要 **协调多个不同的智能体**（OpenClaw、Codex、Claude、Cursor）朝着共同目标努力
- ✅ 你同时运行 **20 个 Claude Code 终端**，却不知道每个人在做什么
- ✅ 你想让智能体 **全天候自主运行**，但仍想审核工作并在需要时介入
- ✅ 你想 **监控成本** 并执行预算限制
- ✅ 你想要一个管理智能体的流程，**感觉就像使用任务管理器**
- ✅ 你想 **用手机** 管理你的自主业务

## Paperclip 解决的问题

| 没有 Paperclip                                                                                                                     | 使用 Paperclip                                                                                                                         |
| ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| ❌ 你打开了 20 个 Claude Code 标签页，却无法追踪每个在做什么。重启后一切都丢失了。                              | ✅ 任务基于工单，对话按线程组织，会话在重启后持久保存。                                                |
| ❌ 你需要从多个地方手动收集上下文，提醒你的机器人你实际在做什么。                                     | ✅ 上下文从任务向上流动，贯穿项目和公司目标——你的智能体始终知道要做什么和为什么。                  |
| ❌ 智能体配置文件夹杂乱无章，你还在重新发明任务管理、智能体之间的通信和协调。 | ✅ Paperclip 为你提供开箱即用的组织结构图、工单、委派和治理——让你运营一家公司，而不是一堆脚本。 |
| ❌ 失控的循环浪费了数百美元的 token，在你还没反应过来时就已经用完了配额。                           | ✅ 成本追踪显示 token 预算，并在超支时对智能体进行节流。管理层通过预算进行优先排序。                    |
| ❌ 你有定期工作（客户支持、社交、报告），却必须记住手动启动它们。                        | ✅ 心跳按计划处理常规工作。管理层进行监督。                                                                |
| ❌ 你有一个想法，就得找到仓库、启动 Claude Code、保持一个标签页打开、还要守在旁边。                                | ✅ 在 Paperclip 中添加任务。你的编码智能体会持续处理直到完成。管理层审核它们的工作。                              |

## 为什么 Paperclip 与众不同

Paperclip 正确处理复杂的编排细节。

|                                   |                                                                                                               |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **原子性执行。**             | 任务检出和预算执行是原子性的，所以不会有重复工作或超支。                      |
| **持久化智能体状态。**       | 智能体在心跳之间恢复相同的任务上下文，而不是从头重启。                     |
| **运行时技能注入。**      | 智能体可以在运行时学习 Paperclip 工作流程和项目上下文，无需重新训练。                      |
| **可回滚的治理。**     | 审批门禁被强制执行，配置变更被版本控制，错误的变更可以安全回滚。        |
| **目标感知的执行。**         | 任务携带完整的目标祖先链，因此智能体始终能看到"为什么"，而不只是一个标题。                        |
| **可移植的公司模板。**   | 导出/导入组织、智能体和技能，带有密钥清洗和冲突处理。                          |
| **真正的多公司隔离。** | 每个实体都按公司划分作用域，因此一次部署可以运行多个具有独立数据和审计跟踪的公司。 |

## Paperclip不是什么

|                              |                                                                                                                      |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **不是聊天机器人。**           | 智能体有工作，而不是聊天窗口。                                                                                  |
| **不是智能体框架。**  | 我们不告诉你如何构建智能体。我们告诉你如何运营一家由它们组成的公司。                                |
| **不是工作流构建器。**  | 没有拖放流水线。Paperclip 建模公司——包括组织结构图、目标、预算和治理。            |
| **不是提示词管理器。**    | 智能体自带提示词、模型和运行时。Paperclip 管理它们工作的组织。               |
| **不是单智能体工具。** | 这是为团队准备的。如果你只有一个智能体，你可能不需要 Paperclip。如果你有二十个——你绝对需要。 |
| **不是代码审查工具。**  | Paperclip 编排工作，而不是拉取请求。带上你自己的审查流程。                                       |

## 快速开始

开源。自托管。无需 Paperclip 账户。

```bash
npx paperclipai onboard --yes
```

如果你已经配置了 Paperclip，重新运行 `onboard` 会保留现有配置。使用 `paperclipai configure` 编辑设置。

或者手动操作：

```bash
git clone https://github.com/paperclipai/paperclip.git
cd paperclip
pnpm install
pnpm dev
```

这会在 `http://localhost:3100` 启动 API 服务器。嵌入式 PostgreSQL 数据库会自动创建——无需设置。

> **要求：** Node.js 20+，pnpm 9.15+

## 常见问题

**典型的配置是什么样的？**
在本地，一个 Node.js 进程管理嵌入式 Postgres 和本地文件存储。对于生产环境，指向你自己的 Postgres，按你喜欢的方式部署。配置项目、智能体和目标——智能体会处理剩下的事情。

如果你是一名独立创业者，可以使用 Tailscale 随时访问 Paperclip。之后，当需要时可以部署到 Vercel 等平台。

**我可以运行多个公司吗？**
可以。一次部署可以运行无限数量的公司，具有完全的数据隔离。

**Paperclip 与 OpenClaw 或 Claude Code 等智能体有何不同？**
Paperclip _使用_ 这些智能体。它将它们编排成一家公司——包含组织结构图、预算、目标、治理和问责制。

**为什么我应该使用 Paperclip，而不是把我的 OpenClaw 指向 Asana 或 Trello？**
智能体编排有很多微妙之处，比如如何协调谁检出了工作、如何维护会话、监控成本、建立治理——Paperclip 为你处理这些。

（自带的工单系统已在路线图中）

**智能体是持续运行的吗？**
默认情况下，智能体按计划的心跳和基于事件的触发器运行（任务分配、@-提及）。你也可以接入像 OpenClaw 这样的持续运行智能体。你带来智能体，Paperclip 进行协调。

## 开发

```bash
pnpm dev              # 完整开发模式 (API + UI，监听模式)
pnpm dev:once         # 完整开发模式，不监听文件变化
pnpm dev:server       # 仅服务器
pnpm build            # 构建全部
pnpm typecheck        # 类型检查
pnpm test:run         # 运行测试
pnpm db:generate      # 生成数据库迁移
pnpm db:migrate       # 应用迁移
```

参见 [doc/DEVELOPING.md](https://github.com/paperclipai/paperclip/blob/master/doc/DEVELOPING.md) 获取完整的开发指南。
